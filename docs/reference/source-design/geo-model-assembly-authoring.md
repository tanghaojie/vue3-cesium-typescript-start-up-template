# Geo 建筑分件、爆炸与飞入拼装制作要求

> 来源规范快照：Cyber-Sight 9697230d7278ae88afb3c82c98e3865181847d08。此文保留来源的功能语义与制作约定；独立应用的当前目录、依赖和部署以 [Geo application design](../../design/geo-workbench.md) 为准。未声明目标浏览器验收通过。

## 目标、来源与适用范围

标准编号 **CS-AM-1**，修订日期 **2026-10-17**。本文件补充[模型制作与地理参考标准](geo-model-authoring.md)，用于后续新建或明确委托重制的建筑。完整制作执行版和逐项目任务书维护在 AIModels 的 `docs/modeling-requirements.md`、`docs/templates/model-brief.md`；两仓库更新时核对同一编号及修订日期。

来源为维护者引用的[Blender建筑爆炸动画会话](chatgpt-conversation://6ad2cbc7-5560-83e9-a3c3-6afb06ff711e)。已读用户原文要求“建筑从无到有、构件逐步飞入拼装”，以及爆炸体逐步搭建。会话助手答复只返回内容引用，无法取得方案/脚本正文。以下命名、时间、路径和文件组织是本次规范，不声称原会话已确认这些参数。

默认新建筑任务同时准备完整成品、可查看的爆炸分解和飞入拼装；维护者明确只要静态资产时可在任务书声明动画不适用及原因。爆炸指建筑构件的分解展示，不默认破碎、坍塌、烟火或刚体破坏模拟。无结构资料时内部构造须标注示意，不将艺术分件称为真实施工或 BIM。

本文件维护制作与交付要求。2026-10-18 增加的普通模型播放入口见[已加载模型动画控制](geo-model-animation.md)，发布协议仍为静态 v1。

## 1. 成品、爆炸与拼装状态

| 状态/文件           | 必须满足                                                                  |
| ------------------- | ------------------------------------------------------------------------- |
| `<id>.glb` 静态成品 | 默认完整装配、无动画依赖，供现行模型目录加载；可做静态批次合并            |
| `<id>-assembly.glb` | 单一 `BUILD_ASSEMBLY` 动画，从空场开始，构件错峰飞入、逐步就位并保持成品  |
| `<id>-explode.glb`  | 单一 `BUILD_EXPLODE` 动画，从成品到有秩序分解并保持；不与拼装曲线同时混播 |
| `<id>.blend`        | 可编辑部件、材质、动画和独立预览集合；保留可恢复的装配矩阵                |

静态、拼装末态和爆炸初态必须对齐同一建筑、锚点、朝向、尺寸、材质与主体轮廓。静态成品没有被暂停在起点的缩小构件。每个动画文件只含一个目的的 clip，防止当前临时预览激活全部动画时产生互相覆盖。

动画文件未激活动画时的节点 TRS 也应保持完整成品；播放时才应用起始关键帧。检查 Blender 导出 rest transform 选项并读取最终 GLB，不能仅把当前时间停在末帧就假定文件默认姿态正确。

## 2. 分件、命名与层级

按建筑逻辑、镜头和飞入粒度拆分。地基/基座、核心筒、各层楼板、柱梁/斜撑、立面分区、屋面/冠部、入口/裙房、重要附属物是建议分类，不要求每栋建筑都有全部类别。机场按航站楼、指廊、屋盖结构和模块组织；壳体按真实或明确示意的板片/结构带组织，不能把同一塔楼模板套给全部建筑。

```text
GEO_ROOT                         固定地理锚点，不参加动画
  STATIC_SITE                    固定自带场地；是否空场保留在任务书声明
  PART_<stable_id>                可动画枢轴/构件节点
    MESH_<stable_id>_<material>   网格及同属构件的窗框、窗灯等
```

- 每个可独立运动的构件有稳定、唯一 `part_id` 和可核对的节点名，例如 `floor_L03_slab_01`。楼层、区域、类别、装配阶段、顺序和依赖写入 `parts.json`，不能只靠 Blender 集合名称推断。
- Blender Collection 用于编辑组织，不等同于导出节点。需要保留的父子关系必须检查最终 GLB 节点树。
- 窗框、玻璃、窗灯、贴花和室内遮挡随所属构件一起运动，防止幕墙飞走后窗灯悬空。共享 mesh/纹理可以复用，独立运动仍保留独立节点；动态构件不依赖未经验证的 GPU 实例变换动画。
- 枢轴设在连接点、构件中心或安装点并记录。统一正比例和稳定父级；有动画后不可直接 Apply Transform 改掉动画基准。禁止带剪切的变换；负缩放先在制作端解决。
- 动画版不得将全部楼层/立面合成一个 mesh 后宣称可以逐件组装。静态优化版可合并，保存其与源构件的映射。LOD 分组时列出 `source_part_ids`。
- 先保存每个构件的装配 TRS，再计算分解和飞入偏移。根锚点与地理对齐变换保持固定，禁止整体飞入代替构件拼装。

## 3. 位置、路径与顺序

WGS84 只表示全楼地理锚点；部件位置、枢轴、路径和爆炸偏移全部使用局部米制，不能给每个楼板写经纬度。沿用当前最终 glTF `+X=北、+Y=上、+Z=东` 的校准结果；Blender 工作坐标与导出转换见制作主规范。

`parts.json` 使用 `gltf-local-y-up`，每个构件的 TRS、路径和偏移都相对清单中明确的固定父节点；默认父节点是 `GEO_ROOT`。复杂嵌套需先转换到目标父局部坐标，不能把 world location 直接写为 local translation。Blender 欧拉角/四元数 WXYZ 不能直接当成 glTF XYZW；旋转输出单位四元数。

默认顺序为基础/基座 → 核心与结构逐层上升 → 楼板/梁柱依赖就位 → 分区幕墙 → 屋面冠部 → 入口、附属细节与场地收尾。可按真实结构和叙事调整，记录依赖和原因；整栋同时缩放、仅逐层显隐或所有构件同时直线冲向中心均不满足“逐步飞入拼装”。

爆炸分解按楼层沿上方拉开、按立面沿外法向展开，或按结构系统分组展开；保留楼层和朝向关系。首次可从楼层高度的 1–3 倍、立面模块尺寸的 0.5–2 倍间距试验，均为可调起点，不是所有建筑固定米数。

飞入起点在建筑外、靠近工作区域，优先从各构件所在侧或上方进入；可设 1–2 个避让点。用构件实际包围盒检查地面、邻件和已完成部件的穿插；对明显无法物理装配的艺术路径做说明。不要用百万米平移隐藏部件，避免精度、包围球和镜头问题。

## 4. 时间轴与运动

默认提案为 **30 fps、24 秒、帧 0–720**，共 720 个帧间隔；属于首次排程起点，按建筑复杂度在任务书定稿。glTF 时间用秒，`t=(frame-frame_start)/fps`。禁止混用绝对 UTC、帧号和 clip 秒数。

| 时间    | 默认画面                         |
| ------- | -------------------------------- |
| 0–1 s   | 空场建立；自带场地是否保留须声明 |
| 1–5 s   | 基础、核心和主要承重结构开始就位 |
| 4–13 s  | 楼层/结构按依赖交错搭建          |
| 11–19 s | 幕墙分区、屋面与冠部逐步拼合     |
| 18–21 s | 入口、附属细节和场地收尾         |
| 21–24 s | 完整成品保持，供切镜和核对       |

每件有 `start_s`、`end_s`、阶段和顺序，同阶段可重叠，依赖必须已达到需要的安装状态。单件飞行可从 0.5–1.5 秒、相邻错峰 0.05–0.20 秒试验，复杂建筑按总时长重排，不能机械累加造成失控时长。

到位以减速收尾，旋转幅度克制、沿短弧插值；弹跳/过冲仅在任务书明确需要时启用。拼装结束后位置、旋转和缩放精确回到保存的装配 TRS，不留浮空、缩小、累积偏移或末帧闪回。爆炸 clip 建议 8–12 秒，末态至少保持 2 秒，具体排程单独记录。

空场兼容基线采用起点在镜头外加极小正比例缩放（例如 `1e-4`），飞行开始前恢复完整尺寸再进入镜头。直接零缩放会产生不可逆变换，只有经目标引擎检查后才使用；非零缩放也需检查首帧漏点、影子和轮廓。不能依靠 Blender `hide_viewport` / `hide_render` 动画或材质 alpha 动画获得核心 glTF 兼容性。

## 5. 导出与可复现脚本

基线只依赖 glTF 核心节点 translation / rotation / scale。约束、曲线路径、驱动、Geometry Nodes 或刚体产生的运动，先烘焙为稳定节点 TRS；有拓扑变化的效果不能当作普通 TRS 烘焙已解决，须改为固定构件方案或另行设计。制作端可用这些工具，不能让播放依赖 Blender 运行时。

每个动画文件优先导出合并后的单 clip，所有构件共用同一 `t=0`，保留原有错峰偏移。不要把每件的起点分别平移到零。旧工具确实只能多 clip 时，记录每个 clip、共同原点、起止和持帧策略，经专门验收后作为例外；不得把两个目的的 clip 同时自动播放。

时间采样可从逐帧开始，经对比后简化。被动画引用的节点用 TRS，不同时写 `matrix`；输入时间严格递增、非负，覆盖首帧、各构件开工/到位和最后保持。Bezier 缓动须采样或正确转换，不能假设任意 Blender 曲线自动等价。压缩/优化后复查首末关键帧和时间偏移。

后续模型交付自己的 `scripts/build_model.py`、`animate.py`、`export.py` 或等效脚本，记录 Blender/导出器版本、入口命令、fps、时长、随机种子、导出选项和输出路径。脚本只重建指定项目资产集合，不删除用户其他场景；重复执行不能叠加复制、材质或关键帧。固定种子、排序和原始装配矩阵，保留无动画源状态。

## 6. 材质、照明及当前消费能力

材质完整遵守主规范的 PBR、UV、纹理、静态夜景及地理参考；拼装/爆炸不把材质临时改成随机色作为最终成品。切开可见的内侧/板厚也有法线与材料，不因动画暴露未处理空壳。

必须设置导出实际使用的 Principled 节点/纹理并检查最终 GLB 的 `pbrMetallicRoughness` 等数据，不能只改 `diffuse_color`。已存在 DEV 样例有视口色与节点色不一致问题，详见[本地预览](geo-assembly-preview.md)；其中按材质名改色和柔光 Shader 是该示例兼容措施，不是新资产可依赖的制作接口。

Blender 预览可使用太阳、面积主补光、HDRI、AgX、曝光和阴影，记录参数；成品 GLB 排除预览相机/灯/HDRI/摄影棚地面。Sight 使用统一太阳、环境与静态 Emissive 夜景；发光不自动照亮邻件，不能以 Blender 的 Bloom 或真实点光效果作为 GLB 正常外观的前提。

| 数据/能力                       | 目前的消费边界                                                                                   |
| ------------------------------- | ------------------------------------------------------------------------------------------------ |
| 静态 `<id>.glb`                 | 可作为 AIModels 发布 v1 的主模型/质量版本                                                        |
| 动画 GLB                        | 通过发布 modes 声明选择独立动画文件；已加载模型识别内嵌动画并显示控制面板                        |
| `parts.json` / `animation.json` | 新制作交付附录，供脚本和人工验收；现行 Geo 不下载、不解析这些文件                                |
| 光照与时间                      | Scene 昼夜继续由唯一 `viewer.clock` 控制；普通模型与 DEV 播放均为独立局部秒数，不改仿真日期/倍率 |

AIModels 发布 v1 的 `resources` 仍只接受 `3d-tiles | geojson`，`variants` 表示精细度，不是播放模式。动画文件通过可选 `modes` 声明，各模式独立列精细度，不塞入未知 `kind`，不覆盖静态成品；缺省规则和运行时选择见[目录设计](geo-ai-models.md)。

## 7. 交付、失败模式与验收

除主规范交付包，增加部件清单 `parts.json`、动画说明 `animation.json`、两种动画 GLB、源脚本、空场/结构/幕墙/成品/爆炸关键帧和时间轴预览。清单至少有稳定 ID、父节点、类别/楼层、枢轴、装配 TRS、爆炸偏移、飞入路径与起止时间、依赖、静态/动画属性；动画说明列 clip 名、文件、fps、秒长、首末状态、持帧和重播约定。字段示例见 AIModels 完整规范，均不是新增网络协议。

静态与动画分别统计大小、面数、节点、primitive/材质、纹理、动画通道/采样数量及峰值同时运动件数。可运动件数可先按约 100–500 个逻辑组试验，复杂建筑必须测量，不作为引擎硬限制或 FPS 承诺；不要逐窗逐螺钉建数万个动画节点。

必须逐项验收：

- [ ] 完整态与静态模型同锚点/尺寸/朝向/材质，主要部件 ID、装配矩阵和依赖可追踪。
- [ ] 空场成立，构件可辨地错峰飞入；中途暂停/任意进度采样与顺播对应，不依赖上一帧状态。
- [ ] 爆炸关系清晰，无破碎语义误用；未出现窗灯漂浮、明显地面穿越或终点穿插。
- [ ] 最后装配矩阵与静态模型一致；推荐平移误差不超过 1 mm、旋转误差不超过 0.01°、缩放误差不超过 `1e-5`，例外附量化依据。这是文件一致性容差，不是建筑测量精度。
- [ ] 0%、25%、50%、75%、100% 及每个阶段边界均检查；完成停留、暂停、重播和回退采样没有跳变。
- [ ] 最终 GLB 材质不是意外灰模；白天、日落、夜间及透明遮挡/细节均核对，动画不劫持昼夜。
- [ ] 静态/动画 GLB 各自通过 Khronos Validator，无错误、警告逐条处置；压缩后重验，脚本入口可复现。
- [ ] 线上交付另验 HTTP、MIME、CORS、完整字节与 SHA-256；GPU/镜头/播放效果保持维护者人工验收，记录设备和版本。
