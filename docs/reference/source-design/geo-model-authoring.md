# Geo 模型制作与地理参考标准

> 来源规范快照：Cyber-Sight 9697230d7278ae88afb3c82c98e3865181847d08。此文保留来源的功能语义与制作约定；独立应用的当前目录、依赖和部署以 [Geo application design](../../design/geo-workbench.md) 为准。未声明目标浏览器验收通过。

## 背景与目标

本标准面向「AI建模世界」的建筑制作、GLB 导出和 Cyber-Sight 浏览录屏：模型需经得起环绕、入口低机位、材质近看和直接 3600 倍速昼夜展示。制作方交付几何、材质及准确标注的地理信息，Sight 按[统一模型渲染标准](geo-model-rendering.md)加载和显示。

2026-10-17 补充 **CS-AM-1** [建筑分件、爆炸与飞入拼装要求](geo-model-assembly-authoring.md)：新建筑默认同时准备静态成品、爆炸分解与从无到有的逐件飞入，明确仅静态任务可声明不适用。AIModels 的 `docs/modeling-requirements.md` 是供建模执行的完整要求，`docs/templates/model-brief.md` 用于填写每栋建筑的资料、参数和验收。

2026-10-03 检查[样本库](https://sample-data-jt.vercel.app/)直接列出的七个独立 GLB：上海中心、环球金融中心、央视总部、台北 101、天府机场和两个 OPPO 版本。七个文件均无图像纹理；其中四个没有 UV，另三个仅全部或部分网格有 UV。除上海中心、台北 101 外，其余坐标命名与加载器不同，或只有外部定位文件。以下是新制作、重导出和验收目标，不表示线上资产已完成整改。

“必须”是新交付资产的验收条件，“建议”是可按资料、镜头和硬件调整的起点。已有模型仍可按当前能力加载，不能因新规范宣称旧模型无法显示。

## 模型优化与场景优化分类

| 类别     | 内容                                                                                                                                       | 责任与交付                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| 模型优化 | 主体轮廓、结构、裙房及自带基座；PBR、UV、纹理、法线、表面变化；窗灯/招牌；部件、爆炸与飞入动画；资源预算；坐标、高程、锚点、朝向；导出验证 | 制作方交付源工程、静态及动画 GLB、部件/时间清单、定位及来源说明、质量版本和报告；本标准详细规定 |
| 场景优化 | 真实邻楼、街区、道路和绿化；地形/影像衔接；街道广场夜间受光；城市反射；区域复用、重复主体排除、分组加载和自动切档                          | 后续场景制作与 Geo 能力扩展；本轮只划分范围，不写成已实现功能                                   |

模型自带铺装、草地和屋面仍需完善材质。周围城市不能靠随机体块或修改主楼材质补回。陆家嘴两栋楼可共用区域环境，OPPO 两版本属于同一地点，机场按大场地分块而非固定塔楼广场半径。

Sight 继续负责标准和渲染，不制作、托管、上传模型，不增加资产后台。默认 Google 混合影像及科技扫描资源用途不变。场景能力另行设计和实施。

## 1. 几何、比例与建筑身份

### 1.1 资料与精度

- 必须记录建筑名称、建成/设计状态、资料日期、照片/轮廓/高度来源和精度。区分测量、公开资料和视觉估算，不把照片重建称为测绘或 BIM。
- 按资料核对主体高度、宽深、主要结构、洞口、屋面与裙房。细节量不能掩盖轮廓、尺度或朝向错误；同一建筑多个版本明确主版本和变体。
- 按镜头组织细节：轮廓、悬挑、主要窗框、斜撑和入口保留几何；远处小接缝、螺钉和细窗格可用法线/纹理。不能把所有重复窗格都拆成独立对象或材质。
- 米制建模，默认加载 scale=1；导出后检查包围盒和尺寸，不靠运行时缩放掩盖单位错误。静态成品排除动画、骨骼、模拟和预览物件；按要求另行交付的动画版保留必要构件节点与 TRS 曲线，不混入静态默认文件。

### 1.2 拓扑、法线与变换

- 清理重复/共面面片、悬空顶点、无关对象和无用内部几何，避免玻璃、窗框、窗灯共面闪烁。保留有用途的室内遮挡层。
- 封闭外壳法线朝外，按曲面/硬边处理平滑和倒角；不要全局平滑磨圆立面，也不要用 doubleSided 掩盖反向面。
- 封闭不透明面默认关闭 doubleSided；叶片、必要薄片经检查后保留。透明不等于必须双面，依据可见面及排序成本决定。
- 处理非均匀/负缩放，检查合成变换后的比例、法线和镜像。允许明确的地理对齐和 glTF 轴向根变换，不机械清空会破坏定位的变换。
- 高模烘焙低模时，低模轮廓、UV 与三角化需稳定，检查法线边界和凹凸方向。近景倒角使用真实尺度，不靠夸张法线模拟轮廓。

## 2. PBR 材质

采用 glTF 2.0 metallic-roughness PBR，区分介电、裸金属、涂层和发光材料。按实景校准颜色、粗糙度与细节；下表参数是试验起点，不是统一强制值。

| 材料                     | 制作要求                                                                                                | 调整起点和常见问题                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 幕墙玻璃                 | 区分清/镀膜玻璃，保留镜面层次、框架、胶缝、室内遮挡和轻微板间变化；远景可用不透明近似，透明区域单独处理 | 普通介电玻璃 metallic=0；roughness 可从 0.12–0.30 试验。镀膜用可导出的 specular/clearcoat 等校准，不用统一高金属度冒充玻璃 |
| 裸铝、钢、铜             | 金属语义，校准金属颜色、粗糙度、倒角和加工纹理                                                          | 连续裸金属通常 metallic=1，roughness 从 0.20–0.45 试验。拉丝随构件方向，远景不得高频闪烁                                   |
| 漆面、涂层金属           | 可见表层按介电材料制作，裸露边缘或磨损另行表达                                                          | 不因基材为钢就把完整漆面设为 metallic=1；磨损须有参考依据                                                                  |
| 石材、混凝土、沥青、橡胶 | metallic=0，补正确尺寸的颗粒、接缝、颜色、粗糙度和法线；近景有可辨细节                                  | roughness 从 0.55–0.95 试验，按磨光/潮湿状态校准；不能共用一个灰色材质                                                     |
| 金属屋面                 | 区分裸面/涂层，校准立缝、板材方向和板间轻微变化                                                         | 机场大面积屋面保持物理尺度，不只用统一银色覆盖                                                                             |
| 草地、植被、木材         | 色彩、粗糙度和形态有层次；重要树冠有可信体积，叶片正确遮罩                                              | 纯绿色平面、等大小球体不足以表达近景景观                                                                                   |
| 窗灯、招牌、轮廓灯       | 独立 Emissive 通道/遮罩，按参考安排明暗、色温与区域                                                     | 不让整片幕墙均匀高亮；自发光不等于照亮相邻表面                                                                             |

同一光照下应能辨认玻璃、石材、金属。不要整栋统一透明 alpha：多层透明面、窗灯和内壁须检查遮挡、排序及成本；无室内结构的透明空壳通常不能形成可信办公室。使用标准 alphaMode，叶片硬遮罩通常用 MASK，确需透光叠层才用 BLEND。

Blender 玻璃、程序化节点、灯光和预览外观不等于可导出的 glTF 效果，必须检查最终文件。建筑主体不使用 Unlit 绕过太阳光照；局部确需 Unlit 时独立说明，其亮度不受统一 PBR 昼夜控制。

设置实际参与导出的 Principled Base Color/纹理、金属度、粗糙度和 Emissive，不以视口 `diffuse_color` 代替节点设置。检查最终 GLB 的材质因子和纹理，避免“视口有色、成品全灰”。源工程预览照明另设集合，记录太阳/主补光/HDRI、色彩管理和曝光；这些参数不是 GLB 运行时光照接口。

## 3. UV、纹理与表面变化

### 3.1 UV 布局

- 每个引用图像纹理的 primitive 必须有对应 TEXCOORD_n，主材质默认 TEXCOORD_0；不能只有部分网格有 UV，其余却引用相同贴图。
- 重复幕墙、屋面和铺装采用米制模块/平铺 UV，窗格、砖缝、颗粒大小与现实一致。数百米立面不靠一张巨大独占贴图获得近景细节。
- 独占 AO/烘焙使用非重叠 UV，通常 TEXCOORD_1，并在 textureInfo 明确 texCoord；第二套 UV 不自动生效。无独占烘焙需求无需强制第二套 UV。
- 平铺材质可有意重叠；标识、独特污渍、窗灯布局和独占烘焙不能误用镜像/重叠。倾斜幕墙、曲面和屋面检查拉伸及接缝。
- 图集按 mipmap、最终分辨率和压缩结果留扩边。2K/4K 可从 8–16 像素扩边试验，低分辨率版本重新检查串色，不只保证最高版本无缝。

### 3.2 通道与色彩空间

| 通道                 | 要求                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------ |
| Base Color           | 颜色及必要 alpha，图像按 sRGB；常量因子遵守 glTF 线性语义。不得烘焙固定太阳、整栋投影或照片拍摄光照          |
| Normal               | 切线空间、线性数据，glTF/OpenGL +Y；DirectX 法线先转换。检查方向、强度与边界，建议导出匹配最终 UV/法线的切线 |
| Roughness / Metallic | 线性数据；metallicRoughnessTexture 的 G=roughness、B=metallic；变化不得让同一材料成为随机花斑                |
| Occlusion            | 线性数据，occlusionTexture 读取 R；用于局部缝隙/结构遮蔽，不替代实时太阳阴影，不烘焙整栋固定暗面             |
| Emissive             | 发光颜色图按 sRGB，因子按 glTF 语义；与白天颜色、必要的独占窗灯布局分离，由 Sight 夜景权重控制               |

ORM 可合并 R=occlusion、G=roughness、B=metallic，但必须分别绑定 occlusionTexture 与 metallicRoughnessTexture。同一图像只在通道的 UV/布局兼容时合并；AO 用独占 UV 而粗糙度用平铺时，分别制作和绑定，不能强行合并导致错位。

法线、粗糙度、ORM 不按 sRGB 处理；颜色不重复 gamma 转换。检查最终图像、采样器、textureInfo 和因子，不以 Blender 内有图片作为完成依据。

### 3.3 密度、分辨率与变化

- 近看重复石材/混凝土可从约 256–512 texel/米试验。这是局部平铺密度，不是整栋必须拥有该密度的独占巨图；依镜头和画幅验收。
- 材质模块先用 1K/2K，重要近景可用 4K；8K 须有镜头收益、显存及加载测量支持，不作为真实感默认方案。检查斜视角、mipmap、压缩后的法线和细线。
- 必须有参考支持的表面变化：板间轻微颜色/粗糙度差、颗粒、胶缝、接缝和必要磨损；新玻璃楼不能全局叠强噪声、随机脏污。
- 变化按板材、楼层或功能区组织，空间固定且可复现；近看有细节，远看无棋盘噪声/闪烁。板间 roughness 差可从约 0.01–0.04 试验，须按照片校准。
- 优先图集、纹理、可导出顶点色和少量合理材质，不靠大量新材质实现差异。顶点色遵守线性语义并检查导出。
- 照片纹理先校正透视、拍摄光照和固定阴影，确认素材可用于交付；通用 CC0 素材仍需尺度、颜色和建筑语境校准。

## 4. 模型夜景与时间稳定性

- 资产提供静态夜景，不内置本地小时、每帧随机窗灯或第二时钟。Sight 使用唯一 viewer.clock 和模型所在地太阳高度；浏览器时区只影响时间显示。
- 窗灯按楼层、房间组和功能区分布，保留暗区、亮度和冷暖差异、室内遮挡及适当退进；默认夜景不采用满楼同亮度或逐帧随机。
- 白天靠玻璃/室内材料，夜间由独立 Emissive 增加窗光，不切换全楼颜色制造昼夜。纹理布局与绑定明确。
- emissiveFactor 保持标准范围，需要高强度时用 KHR_materials_emissive_strength，并检查扩展和比例。Sight 已做运行时适配，不将适配后超范围因子输出为新源资产。
- 自带基座可用克制的独立夜间 Emissive 纹理/表面表达固定灯位受光近似，必须说明性质；不烘进白天颜色，不宣称实时点灯。
- 预览相机、灯光、HDRI 和摄影棚地面不导出。GLB 自发光不自动照亮街道，周边受光和城市反射归场景优化。

## 5. 统一地理参考与坐标格式

### 5.1 地理坐标与高程

1. 水平统一 WGS84 经纬度，参考 EPSG:4326。命名字段明确经纬度，单位十进制度，经度 [-180, 180]、纬度 [-90, 90]；不是按 EPSG 官方轴顺序排列的无标签数组。
2. 已知绝对高度使用 WGS84 椭球高 h，三维参考 EPSG:4979，单位米。正高/海拔 H、建筑高度、地形相对高度不得直接填入；正高转换需明确大地水准面模型和基准，记录 h=H+N 的来源及误差。
3. GCJ-02、BD-09、CGCS2000、TWD97、UTM、地方投影或高程基准须在制作端明确转换，不能只改 CRS 标签。未知参考系标注未知，不猜成 WGS84。底图瓦片校正不等于模型转换。
4. 高程未知时必须省略 ellipsoid_height_m。选择模型坐标后，当前加载器采样地形，椭球体地形用 0；已提供绝对高度会直接使用，不再采样，须确认目标地形适用。
5. 不用“展示默认值 0”表示已知地面高程。只适合无地形展示时在说明中声明，通过输入高度演示；有测量依据的真实椭球高 0 可以保留。
6. 锚点与地形表面不一致时，记录锚点定义和来源，先校准资产/展示输入。当前没有自动解释的 terrain_offset_m、height_mode 等字段，填写 metadata 不会自动应用偏移。

### 5.2 局部米制、原点与轴向

几何保持近原点的局部米制坐标，不将经纬度或百万米 ECEF 直接写入 POSITION，不在节点中再次施加地理定位。WGS84 用于地理锚点；GLB 本体仍是标准 glTF 2.0 右手、Y-up 局部模型。

统一唯一 GEO_ROOT，原点设在有说明的地面基准点，通常为建筑/场地底部中心。地下室、结构深度和不平场地可低于 0，但必须说明基准；改变原点后重新校准坐标。height_m 表示尺寸，定位高度只用 ellipsoid_height_m。

当前 Data 使用 ENU 固定框架和 HeadingPitchRoll，Cesium 默认 upAxis=Y、forwardAxis=Z 再做 glTF 轴向转换。heading=pitch=roll=0 时，经过节点变换的最终 glTF 局部方向与地理方向关系为：

| 最终 glTF 正方向 | 地理局部方向 |
| ---------------- | ------------ |
| +Z               | 东           |
| +X               | 北           |
| +Y               | 上           |

因此不能假设“Blender +X 是东，导出 Y-up 就自动朝向正确”。常规 Blender Z-up 导出将源 +X 保持为 glTF +X、源 +Y 转为 glTF -Z、源 +Z 转为 glTF +Y。可在交付场景采用 Blender +X=北、+Y=西、+Z=上，也可保留工作坐标，在唯一导出根变换中完成同等校准；不能重复旋转两次。

新资产把真实平面朝向校准进几何/根变换，默认加载 scale=1、heading/pitch/roll=0。按北向、入口和路网核对，不以“正面向相机”为朝向。旧资产若需手工旋转，记录实际输入值：当前 heading 是 Cesium 对 ENU 框架的旋转，不是通常“从北开始的建筑方位角”，不能直接套航向数值。

根节点不含无解释大平移，内部物件统一基准。不同质量版本保持锚点、比例、朝向和主要轮廓，不因减面或合并移动原点。机场等大场地记录范围和地面基准；更大范围地形起伏与曲率由后续场景分块处理。

### 5.3 规范字段与当前读取能力

新 GLB 将地理信息只写在活动场景唯一 GEO_ROOT.extras。当前还兼容 glTF 顶层 extras、活动 scene.extras，新资产不重复写多份；不将 asset.extras 或子网格 extras 当作定位入口。

| 字段                                    | 新制作要求                                               | 当前行为                                       |
| --------------------------------------- | -------------------------------------------------------- | ---------------------------------------------- |
| longitude_wgs84 / latitude_wgs84        | 必需，WGS84 锚点的有限数值，不是字符串                   | 读取、范围检查、触发坐标来源选择               |
| ellipsoid_height_m                      | 已知绝对椭球高时提供，未知省略                           | 有限数值直接定位；缺失时选择模型坐标后采样地形 |
| geo_metadata_version                    | 必需，制作规范版本 1                                     | 说明字段，当前不读取或据此拒绝文件             |
| horizontal_crs                          | 必需，EPSG:4326                                          | 说明字段，不自动转换或校验                     |
| vertical_reference                      | 必需，WGS84_ELLIPSOID，描述提供/采样的高度基准           | 说明字段，不执行垂直转换                       |
| coordinate_source / coordinate_accuracy | 必需，来源及 surveyed / reference / approximate 精度分类 | 交付与人工核对，当前不显示或验证               |
| height_source                           | 必需，已知高度注明来源；缺失时 terrain_at_load           | 说明字段，采样由高度字段和用户选择决定         |
| units / local_origin                    | 必需，meters 及可核对的地面锚点描述                      | 不自动修正单位、几何或原点                     |
| height_m                                | 有依据的建筑高度，仅尺寸；其他宽深放交付说明             | 不当海拔或缩放读取                             |

下面是上海中心近似锚点的 metadata 片段，故意省略未知椭球高；不是完整 glTF 或实测结果：

```json
{
  "name": "GEO_ROOT",
  "extras": {
    "geo_metadata_version": 1,
    "horizontal_crs": "EPSG:4326",
    "vertical_reference": "WGS84_ELLIPSOID",
    "longitude_wgs84": 121.5011,
    "latitude_wgs84": 31.23356,
    "coordinate_source": "公开资料建筑中心近似；交付时填写可核对来源",
    "coordinate_accuracy": "approximate",
    "height_source": "terrain_at_load",
    "units": "meters",
    "local_origin": "ground_anchor_at_building_base_center",
    "height_m": 632
  }
}
```

数值不得使用 NaN、Infinity、空字符串或 null 代替未知。提供 ellipsoid_height_m 时，height_source 记录实际来源；不能将示例建筑尺寸 632 复制为定位高度。新增说明字段不改变当前只读取明确坐标的兼容行为。

### 5.4 定位文件与旧模型迁移

可同时提供 placement.json，顶层采用与 GEO_ROOT.extras 相同的规范字段，再记录 URL 和手工 scale、heading、pitch、roll。未知高度仍省略；文件和 GLB 同版本且一致。UI 经度、纬度、高度映射到 longitude_wgs84、latitude_wgs84、ellipsoid_height_m，输入路径的高度始终为显式定位值，不能假定 sidecar 缺高度也会让输入路径采样。

**当前手工模型 URL 不自动请求/读取 placement.json，也不应用 GLB 中的 heading、推荐缩放、height_source 等说明字段。** GLB 自身嵌入规范坐标，朝向在资产中校准或在 UI 手工输入。现行外部数据菜单不提供独立 scene.json 地标入口；[AIModels 目录](geo-ai-models.md)按发布描述显式关联配套资源，不为普通 GLB 猜测或自动请求 sidecar。

| 旧资产                | 重导出要求                                                                                      |
| --------------------- | ----------------------------------------------------------------------------------------------- |
| 环球金融中心          | 经核对的 WGS84 longitude / latitude 改为规范名，检查原点和真实方向；展示高度 0 不当实测值保留   |
| OPPO 两版本、天府机场 | wgs84_longitude / wgs84_latitude 或带 EPSG:4326 的普通字段统一；核对轴向，机场位置/朝向单独校准 |
| 央视总部              | 将外部定位文件中核对后的 WGS84 锚点嵌入唯一 GEO_ROOT；说明近似精度，未知高程省略                |
| 上海中心、台北 101    | 保留规范经纬度，补来源、参考系和原点说明；检查尺寸、高程与方向，不因字段正确就认为测量准确      |

以源工程重导出或经验证的 metadata 更新迁移。本轮不新增旧字段自动识别，不把未知 CRS 的普通经纬度猜成 WGS84，不改写远程源文件。

### 5.5 AIModels 目录的显式定位

以上未知高度省略/运行时采样适用于手工 GLB URL 和模型 metadata 路径。现行 [AIModels 发布目录](geo-ai-models.md) v1 使用 `model.source.json` 生成 `model.json`，其 `placement` 必须显式提供 `height`、scale 和 heading/pitch/roll；目录加载采用该定位，不再次读取 sidecar 或询问坐标。

制作方须分别核对 GLB、制作端 `placement.json` 和发布描述的语义：`ellipsoid_height_m` 与发布 `height` 都不是建筑高度。未知真实高程不能直接以 0 声称测量值；确需发布椭球体演示项时，明确 `terrain: ellipsoid`、0 为展示高度及近似精度，或者先补齐可靠定位。发布 `variants` 可由用户显式选择质量；Scene 三档切换仍不会自动换资产。

## 6. 部件、爆炸与飞入拼装

完整要求见 [CS-AM-1 动画制作专题](geo-model-assembly-authoring.md)。制作任务必须明确：

- 分件系统、楼层/区域、稳定 ID、节点层级、枢轴、装配 TRS、依赖和是否参与动画；窗灯与玻璃跟随所属构件。
- `GEO_ROOT` 地理锚点固定，路径与爆炸偏移使用局部米制；成品、拼装末帧与爆炸首帧同位。
- 默认静态 `<id>.glb`、单 clip `<id>-assembly.glb`、单 clip `<id>-explode.glb` 分别导出；动画保持共同时间原点和真实错峰，不能只做整栋缩放或可见性切换。
- 提供 `parts.json`、`animation.json`、可复现脚本和关键帧证据。此二文件为制作附录，现行 Geo 不自动解析，静态发布协议不因文档新增字段而扩展。
- 材质、光照、定位和资源预算同样适用于动画版；源工程、最终导出文件、线上文件和人工播放效果分别验收。

## 7. 导出与引擎兼容

- 首选自包含 GLB 2.0，内嵌标准图像或已验证 KTX2。外链依赖须有稳定 URL、正确 MIME、CORS 和相对路径，交付清单列明。
- 保留几何、PBR、法线、必要切线、UV、alpha 和规范 extras；只导出资产，排除预览灯光、相机、摄影棚地面和无关对象。检查活动根节点仍有 metadata。
- Blender 程序化/复杂节点、不支持的外观须转换或烘焙。导出成功、源工程预览和 README 都不能证明最终通道保留。
- 锁定 Cesium 1.144.0 / @cesium/engine 26.2.0：基础 PBR、specular、clearcoat、anisotropy、texture transform、KTX2/BasisU、Meshopt、Draco、GPU instancing 有源码支持；具体资产及硬件仍需验证。
- KHR_materials_emissive_strength 由 Sight 适配；Transmission、Volume、IOR 和 KHR_lights_punctual 不作为当前支持能力，不作为正常外观必需前提。extensionsRequired 逐项核对，兼容版本优先标准 PBR、PNG/JPEG。
- 核对 extensionsUsed/Required、实际材质 JSON、图片引用与 UV；特别检查 clearcoat、specular、发光强度是否丢失，不因 Blender 有 Coat Weight 就断言 GLB 含 clearcoat。
- 使用 Khronos glTF Validator，要求无错误；逐条处置警告。压缩后复查尺寸、法线、UV、透明度、发光、坐标和依赖。

## 8. 预算与质量版本

先减少无用几何、材质切换和重复对象，按构件、材质及可见范围组织。可用实例化，但不合成一个超大场地网格造成无效绘制。GLB 大小、三角面、mesh 数和 draw call 分别统计。

制作端建议提供性能、平衡、兼容版本：性能为最佳录屏画质，平衡降低成本，兼容保留轮廓和基础夜景。同地理参考、尺寸与身份。以下为估算起点，不是运行时限制或 FPS 保证：

| 资产类型          | 性能                                      | 平衡                         | 兼容                                           |
| ----------------- | ----------------------------------------- | ---------------------------- | ---------------------------------------------- |
| 单栋塔楼/结构建筑 | 约 20–50 万三角面，重要近景模块可用 4K    | 约 8–20 万，通常 1K/2K       | 约 2–8 万，通常 512/1K                         |
| 机场等建筑群      | 按可见区域分块，整体可从约 40–80 万面估算 | 减少细部与远处设备，保留构型 | 保留航站楼、屋面、主要场地，简化设备/车辆/植被 |

预算例外记录镜头收益、加载时间、纹理/几何占用和设备表现。复用重复纹理，压缩文件大小不代表显存；例如 RGBA8 4K 含完整 mipmap 约 85 MiB，压缩实际占用另测。

Meshopt/Draco 减少几何传输，KTX2/BasisU 改善纹理传输及 GPU 存储；不自动减面或减少批次。低分辨率版本复查扩边和细节，不只是改文件名。

**当前三档 Scene 模式不自动替换主体模型 URL 或切换主体资产版本。** 各主体版本可分别加载验收；生成周边采用 3D Tiles 两级几何并随质量档调整屏幕误差和缓存，见[地标与周边](geo-landmark-context.md)。

## 9. 交付与验收

### 9.1 交付清单

1. 可编辑源工程、实际纹理与依赖、制作/导出版本；附脚本时记录用途和依赖。
2. 新 GLB、稳定 URL、版本/哈希、建筑身份与质量变体，保留可回退源版本。
3. 内置规范 metadata 及一致定位说明：参考系、来源/精度、未知高程、原点、朝向、尺寸、地面基准及手工输入值。
4. 材质/纹理清单：通道、分辨率、UV、色彩空间、来源/许可；标注烘焙与近似。
5. 几何/资源统计、Khronos 报告、警告处置、压缩前后检查；声明未验收镜头或硬件。
6. 白天、日落、夜间及入口/侧后方/近景预览，区分 Blender 与 Sight 截图；标注绝对时刻、地形、坐标、姿态、模式和版本。
7. 适用时提供语义分件、爆炸/飞入拼装源动画和独立 GLB，部件/时间说明、脚本、首中末关键帧及动画一致性检查；只交静态的授权范围与原因写入项目任务书。

### 9.2 制作验收清单

- [ ] 建筑状态、版本、来源与精度明确，轮廓、洞口、尺寸和入口有依据。
- [ ] 材料分类正确，近景有真实尺度细节，玻璃、石材和金属可辨。
- [ ] UV、法线、切线、采样器正确，ORM 和色彩空间无错配；拉伸、串色、远景细线已检查。
- [ ] 表面变化克制、空间固定，无强噪声、过度脏污、固定太阳阴影或拍摄光照。
- [ ] 夜景有区域、暗区和明暗/色温层次；白天发光关闭仍有可信材料，受光近似明确。
- [ ] 唯一 GEO_ROOT 使用规范 WGS84，局部米制和原点明确，尺寸/椭球高分离，未知高程省略，朝向已核对。
- [ ] 排除预览资源，实际扩展/纹理保留，无不支持的必需扩展；Khronos 无错误、警告已处置。
- [ ] 质量版本同锚点/朝向/尺寸，统计、来源、版本和哈希齐全。
- [ ] 分件、动画、脚本、首末状态和交付文件满足 CS-AM-1；静态默认完整，动画不依赖视口隐藏、临时改色或 Blender 灯光。

### 9.3 Sight 人工验收

同一构图对比正午、日落、蓝调和夜间，补入口低机位、侧后方、材料近景与远景环绕。核对坐标选择、接地、北向、比例、透明遮挡、阴影、窗灯和反射；直接 3600 倍速检查无资产内置灯光跳变/随机闪烁，分别记录三档模式及不同质量 URL。

以唯一 viewer.clock 标注绝对时刻；浏览器时区与建筑所在地太阳不同不视为模型错误。现有环境图不自动包含邻楼反射，周围城市不足不能归因于 UV。Blender 和静态验证不替代 Cesium GPU/录屏验收，遵循仓库前端人工验收边界。

## 职责、接口与数据流

本标准不新增后端/公共 API、依赖或运行时 Schema。资料 → 局部建模 → PBR / UV / 纹理 → WGS84 锚点及轴向校准 → 导出验证 → 外部托管 → Data 加载与坐标选择 → Scene 统一昼夜。

涉及动画时在制作端增加“语义分件 → 保存装配矩阵 → 排程/路径 → TRS 烘焙 → 静态与动画独立导出”。AIModels 目录消费静态主模型；2026-10-18 已为实际加载的动画 GLB 接入[资源行播放控制](geo-model-animation.md)，不自动发现静态主文件旁的动画，也不解析制作附录。DEV 固定样例的配色与柔光仍是独立兼容路径。

读取和定位入口仍为 Geo 的 model-asset.ts、data-browser.ts，渲染由 Scene 和唯一 Clock 管理。说明字段不执行脚本、不自动转换参考系。主体源资产整改独立于已交付的[自动周边街区](geo-landmark-context.md)；生成环境不表示主体 GLB 已重制。
